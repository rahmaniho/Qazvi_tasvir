# چندزبانه‌سازی سایت قزوین تصویر (۱۰ زبان)

سایت فارسی (RTL) به ۱۰ زبان منتشر می‌شود: **فارسی (پیش‌فرض)، دری، عربی، انگلیسی،
ترکی، روسی، آلمانی، فرانسوی، چینی، کره‌ای، ژاپنی.**

> «فقط ترجمه یکبار انجام شود» — هر عبارت دقیقاً یک‌بار ترجمه می‌شود، در یک واژه‌نامهٔ
> قفل‌شده، و همان ترجمه در همهٔ جای سایت بازاستفاده می‌شود.

---

## چطور کار می‌کند

```
index.html  ──►  tools/extract-i18n-strings.py  ──►  i18n/strings.fa.json
(صفحهٔ مبدأ)                                          i18n/worksheet.csv
                                                             │
   مترجم: i18n/<lang>.json را پر می‌کند  ◄──────────────────┘
                                                             │
        i18n/<lang>.json  ──►  tools/build-i18n-site.py  ──►  /<lang>/index.html
                                                             sitemap.xml
```

| مسیر | نقش |
|---|---|
| `tools/i18n_core.py` | پویشگر مشترک: هر رشته با **آفست دقیق بایت در سند مبدأ** و امضای تگ‌های درونی‌اش ثبت می‌شود. استخراج و ساخت از همین یک موتور استفاده می‌کنند، پس کلید هرگز دو معنا نمی‌گیرد. |
| `tools/extract-i18n-strings.py` | رشته‌های HTML + متادیتا + ویژگی‌ها + **JSON-LD** را بیرون می‌کشد؛ کلیدهای پایدار می‌سازد؛ `worksheet.csv` را برای مترجم می‌نویسد. |
| `tools/build-i18n-site.py` | برای هر زبان یک صفحهٔ واقعی می‌سازد (نه ریدایرکت جاوااسکریپتی): `lang`/`dir`، سوییچر زبان، `hreflang`، `x-default`، `canonical`، `og:locale`، عنوان/توضیح هر مسیر، `sitemap.xml`. |
| `tools/check-html.py` | بررسی ساختار HTML خروجی‌ها (تگ‌های بسته‌نشده، تودرتویی). |
| `tools/smoke-test.mjs` | آزمون زمان اجرا در jsdom: هر صفحه، هر ۱۳ مسیر هش، سوییچر زبان و `hreflang` (نیازمند `npm i jsdom`؛ در خود سایت هیچ گام ساختی وجود ندارد). |
| `tools/check-css-direction.py` | گیت جهت صفحه: برندهٔ آبشار `direction` روی `<html>` را برای هر دو حالت `dir="ltr"`/`dir="rtl"` حل می‌کند. (ویژگی `dir` فقط یک presentational hint است و هر قاعدهٔ CSS آن را باطل می‌کند.) |
| `tools/check-no-content-drift.py` | گیت ضد‌رانش: اثبات می‌کند ساخت سایت، یک کلمه از متن فارسی را تغییر نداده است. |
| `i18n/GLOSSARY.md` | واژه‌نامهٔ قفل‌شده: نام رسمی شرکت، داده‌های ثبتی، ~۵۰ اصطلاح در ۱۰ زبان، قاعدهٔ ارقام، نقشهٔ فونت و `hreflang`. |
| `i18n/strings.fa.json` | نقشهٔ رشته‌ها (مرجع ماشینی) + اثر انگشت هر رشته. |
| `i18n/worksheet.csv` | همان رشته‌ها در قالب اکسل، یک ستون برای هر زبان. |

### اجرا

```bash
python3 tools/extract-i18n-strings.py           # استخراج رشته‌ها از index.html
python3 tools/build-i18n-site.py --scaffold en  # ساخت قالب ترجمهٔ انگلیسی
python3 tools/build-i18n-site.py --check        # اعتبارسنجی، بدون نوشتن
python3 tools/build-i18n-site.py                # ساخت همهٔ زبان‌های آماده

# آزمون‌های تأیید
python3 tools/check-html.py index.html en/index.html
python3 tools/check-css-direction.py
python3 tools/check-no-content-drift.py
cd /tmp && npm i jsdom && QT_ROOT=<repo> node <repo>/tools/smoke-test.mjs
```

## تضمین‌هایی که سازنده می‌دهد

اگر یکی از این‌ها نقض شود، **زبان ساخته نمی‌شود** (به‌جای انتشار صفحهٔ نیمه‌ترجمه):

1. **پوشش کامل** — هر کلید `strings.fa.json` ترجمه شده باشد.
2. **ساختار تگ‌ها** — توالی تگ‌های درون‌خطی هر رشته (مثل `<strong>`) دقیقاً حفظ شود.
3. **داده‌های ثبتی** — شناسهٔ ملی، شمارهٔ ثبت، کد اقتصادی، تاریخ تأسیس و تلفن‌ها
   بی‌کم‌وکاست (فقط شکل رقم بر اساس زبان) در ترجمه بمانند.
4. **خط نوشتاری** — در زبان‌های لاتین هیچ حرف فارسی/عربی نماند؛ در عربی خط فارسی
   (ی/ک) به‌کار نرود.
5. **ساختار سند** — ترجمه هرگز جای تگی را جابه‌جا نکند (گیت سخت روی توالی تگ‌ها).
6. **اصالت ترجمه** — اثر انگشت متن فارسی داخل فایل ترجمه ذخیره می‌شود؛ اگر بعداً متن
   مبدأ تغییر کند، ساخت متوقف می‌شود و رشتهٔ تغییر‌یافته دوباره ترجمه خواهد شد.
7. **قاعدهٔ ارقام** — خودکار اعمال می‌شود: فارسی/دری ارقام فارسی (۰-۹)، بقیهٔ زبان‌ها
   ارقام لاتین. تنها استثنا: رشته‌هایی که عمداً هر دو تقویم را کنار هم دارند
   (مثل «۱۴۰۴ / 2026») دست‌نخورده می‌مانند.
8. **رانش صفر** — صفحهٔ فارسی پس از ساخت، بیت‌به‌بیت همان متن قبلی را دارد.
9. **جهت صفحه** — قاعدهٔ CSS نباید ویژگی `dir` را باطل کند؛ گیت
   `check-css-direction.py` این را قطعی بررسی می‌کند (باگ واقعی: یک قاعدهٔ
   `html { direction: rtl }` کل صفحهٔ انگلیسی را راست‌به‌چپ می‌چید).

## راهبرد ترجمه (چرا کیفیت تضمین می‌شود)

- **واژه‌نامهٔ ابتدا** (`GLOSSARY.md`): نام شرکت، نام مدیرعامل، اصطلاحات کلیدی و
  معادل‌های حقوقی هر زبان، **پیش از** شروع ترجمه قفل شد تا هر عبارت فقط یک ترجمه داشته باشد.
- **ترتیب فازها** — اول انگلیسی (زبان مرجع بین‌المللی)، سپس دری و عربی (هم‌ریشه با
  فارسی و نزدیک به ذائقهٔ مشتری)، بعد ترکی/روسی/آلمانی/فرانسوی، و در پایان
  چینی/کره‌ای/ژاپنی.
- **نام‌های خاص** دو شکل دارند: شکل لاتین «Qazvin Tasvir Company» و شکل بومی
  (مثلاً «شركة قزوين تصوير» در عربی). نام اشخاص در زبان‌های لاتین با آوانگاری
  استاندارد و در عربی/دری با رسم‌الخط همان زبان نوشته می‌شود.
- **بازبینی بومی** برای ۶ مورد باقی‌مانده (فهرست در `GLOSSARY.md`) توصیه می‌شود؛ تا آن
  زمان ترجمه‌ها قابل انتشار هستند، اما امضای نهایی با یک ناظر بومی است.
